Turn a cheap VPS into a small PaaS

Declare apps in apps.yml, build them on GitHub runners, and deploy to Dokku with zero downtime and automatic HTTPS. Managed entirely from GitHub Actions: nothing runs on your machine except init-github.sh, once.

Use this template Read the setup

Free and open source under the MIT license.

What you get

  • Apps as code. Declare apps in apps.yml, push, and they are created on the server.
  • No builds on the VPS. Images are built on GitHub runners, so a 1 vCPU / 1–4 GB box is enough.
  • Zero-downtime deploys and automatic HTTPS with Let's Encrypt.
  • Basic hardening: UFW, fail2ban, key-only SSH, unattended upgrades and swap.

Requirements

Have these ready before you start.

  • A VPS running Ubuntu 22.04 or 24.04 (any provider) with root SSH access.
  • A domain with a wildcard DNS record pointing to the VPS: A *.example.com → <VPS IP>. Every new app then gets a subdomain with no DNS changes.
  • gh installed and logged in (gh auth login). Only needed for the one-time setup.

Setuponce · 5–10 min

From an empty VPS to a working PaaS. The bootstrap is idempotent, so you can re-run it safely.

  1. Create your copy of the repo

    Click Use this template (or fork), then clone your copy.

  2. Fill in your settings and run the setup script

    Edit .env after copying it, then run the script. It generates the SSH keys and writes every secret and variable to your repo.

    Terminal
    $ cp .env.example .env
$ scripts/init-github.sh
  3. Authorize the root key on the VPS

    The script prints a public key. Add it on your provider's “SSH keys” page, or with ssh-copy-id.

  4. Private repo only: allow access from your app repos

    Go to Settings → Actions → General → Access and choose “Accessible from repositories owned by the user”, so your app repos can call deploy-dokku.yml.

  5. Run the bootstrap

    Check your own SSH access first.The bootstrap disables SSH password login, but only if it finds a key in /root/.ssh/authorized_keys. Make sure you can log in with your own key too.

    Open Actions → Bootstrap VPS → Run workflow. It takes 5–10 minutes.

Secrets & variables

init-github.sh sets all of these for you. This list is for reference, or for setting them by hand.

NameTypeWhat it is
VPS_HOSTvariableVPS IP or hostname
VPS_KNOWN_HOSTSvariableVPS host key (protects against MITM)
DOKKU_DOMAINvariableBase domain, e.g. example.com
LETSENCRYPT_EMAILvariableEmail for Let's Encrypt notices
GHCR_USERvariableGitHub user that owns the images
DOKKU_TAGvariable · optionalDokku version to install
SWAP_SIZEvariable · optionalSwap file size, default 2G; 0 disables it
VPS_SSH_KEYsecretRoot key, used only by this repo's workflows
DOKKU_CI_SSH_KEYsecretDeploy key (dokku user, not root), copied into your app repos
GHCR_TOKENsecret · optionalClassic PAT with read:packages, so the VPS can pull private images. Fine-grained tokens don't work with ghcr.io.
GH_ADMIN_TOKENsecret · optionalFine-grained PAT with access to your app repos and Secrets: Read and write, so Sync can write their deploy secrets. Without it, set them by hand.

Adding an app

Repeat this for every app you want to host.

  1. Prepare the app's repo

    Add a Dockerfile and copy examples/deploy.yml to .github/workflows/deploy.yml. In it, replace YOUR-USER and app:.

  2. Declare the app in apps.yml and push
    apps.yml
    apps:
  - name: my-api
    memory: 512m
    repo: YOUR-USER/my-api

    The Sync apps workflow creates the app in Dokku and writes the DOKKU_* secrets into the app's repo.

  3. Push to main in the app's repo

    It goes live at https://my-api.example.com. HTTPS is enabled on the first deploy.

See the comments in apps.yml for every field: custom domains, port, memory, and so on.

Operations

Day-to-day tasks. Everything here is plain Dokku over SSH; replace VPS with your server's host.

Logs
Follow an app's logs
$ ssh dokku@VPS logs my-api -t
Environment variables

Setting a variable restarts the app.

Set a variable
$ ssh dokku@VPS config:set my-api KEY=value
Rollback

Re-run the deploy workflow of an earlier commit: Actions → Deploy → Re-run.

Database

Install the Postgres plugin once as root, then create a database and link it. Linking injects DATABASE_URL into the app.

Add Postgres
$ ssh root@VPS dokku plugin:install https://github.com/dokku/dokku-postgres.git
$ ssh dokku@VPS postgres:create my-db
$ ssh dokku@VPS postgres:link my-db my-api
Deleting an app

Removing an app from apps.yml deletes nothing, on purpose. To delete it:

Destroy an app
$ ssh root@VPS dokku apps:destroy my-api --force
Upgrading Dokku

Change the DOKKU_TAG variable (or the default in scripts/bootstrap-vps.sh) and run Bootstrap VPS again.

Small servers

This setup is built to run on a 1 GB box.

  • Dokku itself uses very little (nginx + Docker).
  • During a deploy, the old and new containers run side by side for wait_to_retire seconds (30 by default). The swap file absorbs that spike.
  • Set memory on each app so one app can't take down the others.

Repository layout

What each file in this repo does.

FilePurpose
apps.ymlApp declarations. Edit and push; the workflow applies them to the VPS.
.github/workflows/bootstrap.ymlPrepares the VPS: hardening, Dokku, Let's Encrypt, ghcr.io login and deploy key. Manual and idempotent.
.github/workflows/sync-apps.ymlApplies apps.yml. Runs on every push that changes it, or manually.
.github/workflows/deploy-dokku.ymlReusable build-and-deploy workflow, called by your app repos.
examples/deploy.ymlThe workflow to copy into each app repo.
scripts/bootstrap-vps.shRuns on the VPS during bootstrap.
scripts/sync-apps.shRuns during sync.
scripts/init-github.shOne-time setup: generates keys and writes the secrets and variables.
