Requirements

What you need

  • A VPS running Ubuntu 22.04/24.04 (any provider) with root SSH access.
  • A domain with a wildcard DNS record pointing to the VPS: A *.example.com → <VPS IP>. Every new app then gets a subdomain with no DNS changes.
  • gh installed and logged in (gh auth login), only for the one-time setup.

Setup · once

From empty VPS to PaaS in five steps

The bootstrap takes 5–10 minutes and can be re-run safely.

  1. Click Use this template (or fork), then clone your copy.
  2. Fill in your settings and run the setup script: 
    $ cp .env.example .env
$ scripts/init-github.sh
  3. Authorize the root key the script prints on the VPS (your provider's "SSH keys" page, or ssh-copy-id).
  4. If your repo is private: Settings → Actions → General → Access → "Accessible from repositories owned by the user", so your app repos can call deploy-dokku.yml.
  5. Actions → Bootstrap VPS → Run workflow.
⚠️ The bootstrap disables SSH password login, but only if it finds a key in /root/.ssh/authorized_keys. Make sure you can log in with your own key too.

Configuration

Secrets and variables

init-github.sh sets all of these for you.

VPS_HOSTvariableVPS IP or hostname
VPS_KNOWN_HOSTSvariableVPS host key (protects against MITM)
DOKKU_DOMAINvariableBase domain, e.g. example.com

GHCR_USERvariableGitHub user that owns the images

DOKKU_CI_SSH_KEYsecretDeploy key (dokku user, not root), copied into your app repos

GH_ADMIN_TOKENsecret · optionalFine-grained PAT with access to your app repos and Secrets: Read and write, so Sync can write their deploy secrets. Without it, set them by hand

Adding an app

Declare it, push it, it's live

  1. In the app's repo, add a Dockerfile and copy examples/deploy.yml to .github/workflows/deploy.yml. Replace YOUR-USER and app:.
  2. Declare the app in apps.yml and push. Sync apps creates it in Dokku and writes the DOKKU_* secrets into the app's repo.
  3. Push to main in the app's repo. HTTPS is enabled on the first deploy.

See the comments in apps.yml for every field: custom domains, port, memory, and so on.

apps.yml
apps:
  - name: my-api
    memory: 512m
    repo: YOUR-USER/my-api

$ git push
✓ Sync apps: created my-api
✓ Deploy: https://my-api.example.com

Operations

Day-to-day

Everything else is plain Dokku over SSH.

Logs

ssh dokku@VPS logs my-api -t

Environment variables

ssh dokku@VPS config:set my-api KEY=value (restarts the app)

Rollback

Re-run the deploy workflow of an earlier commit (Actions → Deploy → Re-run).

Database

dokku plugin:install https://github.com/dokku/dokku-postgres.git as root, then postgres:create my-db and postgres:link my-db my-api (injects DATABASE_URL).

Deleting an app

Removing it from apps.yml deletes nothing, on purpose. To delete: ssh root@VPS dokku apps:destroy my-api --force

Upgrading Dokku

Change the DOKKU_TAG variable (or the default in scripts/bootstrap-vps.sh) and run Bootstrap again.
